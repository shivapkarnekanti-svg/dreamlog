Verify this build

Dreamlog says it cannot read your dreams. You should not have to take our word for it. Every release is built by GitHub Actions from a tagged commit of the public code, and the SHA-256 hash of every file it publishes is listed in build-hashes.txt. Rebuild the same commit yourself and the hashes must match what this site serves.

1. Rebuild the tagged commit

git clone https://github.com/shivapkarnekanti-svg/dreamlog
cd dreamlog
git checkout m5-done   # use the tag shown in the GitHub release
npm ci
# public Firebase web config (not secret):
export VITE_FIREBASE_API_KEY=AIzaSyAYx8pkrmZ9AnTG_62iopJV3W-8kpjhI8A
export VITE_FIREBASE_AUTH_DOMAIN=dreamlog-app-5754.firebaseapp.com
export VITE_FIREBASE_PROJECT_ID=dreamlog-app-5754
export VITE_FIREBASE_APP_ID=1:619711301309:web:9281b1048412702a9959d4
export VITE_USE_EMULATORS=false
npm run build

2. Compare the hashes

curl -s https://dreamlog-app-5754.web.app/build-hashes.txt | diff - dist/build-hashes.txt

No output means every file matches.

3. Check where the page can send data

The page is served with a Content-Security-Policy that only allows network calls to your browser's own origin, Firebase (sign-in and storage of encrypted data), and api.anthropic.com (only when you press “Analyze with AI”). Open your browser's developer tools, Network tab, and watch: dream text should never appear in a request except that one button.

Want to avoid trusting any single deployment? Fork the repo, create your own free Firebase project and deploy it. The README explains how.
